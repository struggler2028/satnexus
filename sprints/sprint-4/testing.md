# Sprint 4 – Testing and Validation

## 1. Testing Objective

The objective of Sprint 4 testing is to verify network analytics, connectivity calculations, communication cost analysis, reliability evaluation and performance monitoring.

## 2. Planned Test Cases

| Test ID | Test Scenario | Expected Result |
|---|---|---|
| TC-30 | Count total satellites | Correct total is displayed |
| TC-31 | Count operational satellites | Active satellite count is correct |
| TC-32 | Count failed satellites | Failed satellite count is correct |
| TC-33 | Calculate active communication links | Active link count is correct |
| TC-34 | Identify disconnected satellites | Disconnected satellites are reported |
| TC-35 | Calculate shortest route cost | Correct route cost is displayed |
| TC-36 | Calculate average link cost | Correct average is calculated |
| TC-37 | Analyze network after satellite failure | Updated network statistics are displayed |
| TC-38 | Record routing execution time | Execution time is recorded |
| TC-39 | Track successful and failed messages | Transmission statistics are correct |
| TC-40 | Display network statistics dashboard | Dashboard displays updated information |

## 3. Testing Approach

Testing will be performed using:

- Functional testing.
- Connectivity verification.
- Cost calculation testing.
- Failure scenario testing.
- Performance measurement.
- Graphical interface testing.
- Integration testing.

## 4. Testing Results

Actual results, pass/fail status and supporting screenshots will be recorded after running the test cases.

| Test ID | Actual Result | Status |
|---|---|---|
| TC-30 to TC-40 | Pending execution | Not Tested |

## 5. Defect Tracking

Incorrect statistical calculations, performance measurement issues, outdated dashboard values and graphical rendering problems will be documented and resolved.

## 6. Conclusion

Sprint 4 testing will validate the analytical and performance monitoring capabilities of the SatNexus satellite communication network.
