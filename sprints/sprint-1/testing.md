# Sprint 1 – Testing and Validation

## 1. Testing Objective

The objective of Sprint 1 testing is to verify the correctness of satellite creation, graph representation, communication links and graphical visualization.

## 2. Planned Test Cases

| Test ID | Test Scenario | Expected Result |
|---|---|---|
| TC-01 | Add a valid satellite | Satellite is added |
| TC-02 | Add duplicate satellite ID | Operation is rejected |
| TC-03 | Add a valid communication link | Link is created |
| TC-04 | Connect to an invalid satellite ID | Operation is rejected |
| TC-05 | Create a self-connection | Operation is rejected |
| TC-06 | Add a duplicate communication link | Operation is rejected |
| TC-07 | Add a zero or negative weight | Operation is rejected |
| TC-08 | Display network | Graph connections are displayed |
| TC-09 | Launch graphical window | Network visualization appears |
| TC-10 | Close graphical window | Application terminates |

## 3. Testing Approach

Testing will be performed using:

- Functional testing.
- Input validation.
- Graph connectivity verification.
- Graphical interface verification.
- Manual execution testing.

## 4. Testing Results

Actual results, pass/fail status and supporting screenshots will be recorded after running the test cases.

| Test ID | Actual Result | Status |
|---|---|---|
| TC-01 to TC-10 | Pending execution | Not Tested |

## 5. Defect Tracking

Any compilation errors, incorrect graph connections or graphical rendering issues will be documented and resolved.

## 6. Conclusion

Sprint 1 testing will validate the initial foundation of the SatNexus satellite communication network.
